# 06. Терминальный UI

## Назначение

Терминальный UI — основной интерфейс пользователя склада. Он должен быть простым, крупным и понятным, потому что используется рядом со шкафом хранения.

Рекомендуемый вариант MVP:

- локальный браузер;
- kiosk mode;
- Jinja2 + HTMX или простой HTML/JS;
- backend и UI работают на одном мини-ПК или Raspberry Pi.

## Общие требования

- Крупные кнопки.
- Минимум текста на экране.
- Любое действие после RFID.
- Ошибки показывать явно.
- При активной сессии показывать блокирующий экран.
- Не скрывать от пользователя, какая ячейка открыта.
- Не менять остатки на этапе открытия.
- Все финальные изменения только после подтверждения.

## Экран 1. Ожидание RFID

Текст:

```text
Приложите RFID-карту
```

Дополнительно:

- индикатор состояния системы;
- если backend видит активную сессию, сразу показывать блокирующий экран;
- если есть ошибка оборудования, показать предупреждение.

## Экран 2. Главное меню

Пример:

```text
Здравствуйте, Иван

1. Найти товар
2. Положить товар
3. Забрать товар
4. Что в ячейке?
5. Все товары с остатками
6. Все ячейки с товарами
7. Инвентаризация
8. Открыть ячейку
```

Кнопки должны отображаться с учетом роли.

Например, для `user` можно скрыть:

- инвентаризацию;
- открытие ячейки без операции, если запрещено политикой;
- административные действия.

## Экран 3. Поиск товара

Поля:

- строка поиска;
- кнопка `Найти`;
- возможность ввода или сканирования штрихкода.

Подсказка:

```text
Введите название, артикул или штрихкод
```

Результаты:

| Товар | SKU | Остаток | Действия |
|---|---|---:|---|
| Кабель HDMI 2м | HDMI-2M | 12 шт | Открыть |

## Экран 4. Карточка товара

Показывать:

- название;
- SKU;
- штрихкод;
- единицу измерения;
- общий остаток;
- ячейки с количеством.

Пример:

```text
Кабель HDMI 2м
SKU: HDMI-2M
Штрихкод: 460000000001
Общий остаток: 12 шт

Ячейки:
- Ячейка 2: 5 шт
- Ячейка 5: 7 шт

[Положить]
[Забрать]
[История]
[Назад]
```

## Экран 5. Пополнение товара

Шаги:

1. Выбор товара.
2. Выбор ячейки.
3. Ввод количества.
4. Подтверждение.
5. Открытие ячейки.
6. Подтверждение закрытия.
7. Подтверждение операции.

Перед открытием показать:

```text
Положить товар

Товар: Кабель HDMI 2м
Ячейка: 2
Количество: 5 шт

[Открыть ячейку]
[Отмена]
```

## Экран 6. Выдача товара

Шаги:

1. Выбор товара.
2. Показ ячеек с остатком.
3. Выбор ячейки.
4. Ввод количества.
5. Проверка остатка.
6. Открытие ячейки.
7. Подтверждение закрытия.
8. Подтверждение выдачи.

Перед открытием показать:

```text
Забрать товар

Товар: Кабель HDMI 2м
Ячейка: 2
Доступно: 5 шт
Количество к выдаче: 3 шт

[Открыть ячейку]
[Отмена]
```

## Экран 7. Ячейка открыта

Пример:

```text
Ячейка 2 открыта

Операция: Забрать товар
Товар: Кабель HDMI 2м
Количество: 3 шт

Выполните операцию, закройте ячейку и нажмите кнопку.

[Ячейка закрыта]
```

В MVP кнопка `Ячейка закрыта` вручную подтверждает закрытие.

В будущем перед переходом дальше можно проверять датчик закрытия.

## Экран 8. Подтвердите операцию

Для пополнения:

```text
Подтвердите пополнение

Товар: Кабель HDMI 2м
Ячейка: 2
Количество: +5 шт

[Подтвердить]
[Отменить операцию]
```

Для выдачи:

```text
Подтвердите выдачу

Товар: Кабель HDMI 2м
Ячейка: 2
Количество: -3 шт

[Подтвердить]
[Отменить операцию]
```

Важное правило:

До нажатия `Подтвердить` остаток не меняется.

## Экран 9. Активная незавершенная сессия

Показывается, если уже есть активная сессия.

```text
Есть незавершенная операция

Ячейка: 2
Пользователь: Иван
Операция: Забрать товар
Открыта: 14:32

Новая ячейка не может быть открыта, пока эта операция не завершена.

[Ячейка закрыта]
[Отменить операцию]
[Вызвать администратора]
```

Правила:

- новая ячейка не открывается;
- пользователь должен завершить текущую операцию;
- если пользователь не имеет прав на отмену, кнопка отмены должна быть скрыта или требовать администратора.

## Экран 10. Что в ячейке

Сценарий:

```text
RFID
-> Что в ячейке?
-> выбрать номер ячейки
-> показать список товаров и количество
```

Пример:

```text
Ячейка 2

- Кабель HDMI 2м: 5 шт
- Переходник USB-C: 12 шт

[Назад]
```

## Экран 10а. Все товары с остатками

Сценарий:

```text
RFID
-> Все товары с остатками
-> показать список товаров с ячейками и количеством
```

Показывать:

- товар;
- SKU;
- ячейка;
- количество.

Правила:

- вывод постраничный;
- пользователь выбирает размер страницы: `20`, `50` или `100` строк;
- пользователь может включить `Показать товары с нулевым остатком`;
- пользователь может включить `Показать товары без ячеек`;
- строки сортируются по названию товара, затем по номеру ячейки;
- по умолчанию показываются положительные остатки.

## Экран 10б. Все ячейки с товарами

Сценарий:

```text
RFID
-> Все ячейки с товарами
-> показать список ячеек с товарами и количеством
```

Показывать:

- ячейка;
- товар;
- SKU;
- количество.

Правила:

- вывод постраничный;
- пользователь выбирает размер страницы: `20`, `50` или `100` строк;
- строки сортируются по номеру ячейки, затем по названию товара;
- показываются положительные остатки.

## Экран 11. Ошибка

Типовые ошибки:

```text
Ключ не найден
```

```text
Нет прав для этой операции
```

```text
Недостаточно товара в ячейке
```

```text
Не удалось открыть ячейку. Обратитесь к администратору.
```

```text
Есть незавершенная операция. Сначала завершите ее.
```

## Требования к UX

- После завершения операции возвращаться на экран RFID.
- Не держать пользователя авторизованным бесконечно.
- Желательно добавить таймаут неактивности.
- Все опасные действия требуют подтверждения.
- Номер открытой ячейки должен быть виден крупно.
