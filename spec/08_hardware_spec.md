# 08. Аппаратная часть

## Цель

Обеспечить открытие конкретной ячейки после команды backend и RFID-авторизации.

## MVP на 8 ячеек

Рекомендуемый набор:

- мини-ПК или Raspberry Pi;
- USB RFID-считыватель;
- 8 электромеханических шкафных замков 12 В;
- релейный модуль на 8 каналов;
- отдельный блок питания 12 В для замков;
- провода, клеммы, предохранители;
- корпус/шкаф с ячейками.

## Требования к RFID-считывателю

Для MVP удобен USB RFID-считыватель, работающий как HID-клавиатура.

Принцип:

```text
пользователь прикладывает карту
-> считыватель вводит UID как текст
-> UI отправляет UID в backend
```

Плюсы:

- не нужен специальный драйвер;
- легко тестировать;
- работает как обычная клавиатура.

Нужно проверить:

- формат UID;
- добавляет ли считыватель Enter после UID;
- стабильность чтения одной и той же карты;
- совместимость с выбранными RFID-картами.

## Требования к замкам

Рекомендуемый тип:

- 12 В электромеханические шкафные замки;
- fail-secure;
- открытие коротким импульсом;
- без питания остаются закрытыми.

Импульс открытия:

```text
0.5-1.0 сек
```

Важно:

- питание замков не брать напрямую с Raspberry Pi;
- использовать отдельный блок питания 12 В;
- учитывать пусковой ток замков;
- добавить защиту от переполюсовки и короткого замыкания, если возможно.

## Релейные модули для MVP

Вариант 1: USB-реле на 8 каналов.

Плюсы:

- проще подключить;
- достаточно для MVP;
- удобно для прототипа.

Минусы:

- хуже масштабирование до 50 ячеек;
- возможна зависимость от драйверов конкретной платы.

Вариант 2: RS485 Modbus RTU реле на 8 каналов.

Плюсы:

- лучше масштабирование;
- несколько плат на одной линии;
- адресация контроллеров;
- промышленнее.

Минусы:

- сложнее настройка;
- нужен USB-RS485 адаптер;
- нужно аккуратно настроить адреса плат.

## Рекомендуемая стратегия

Для быстрого MVP:

```text
USB RFID + USB-реле 8 каналов + 8 замков 12 В
```

Для версии с расширением:

```text
USB RFID + USB-RS485 + Modbus RTU релейные модули по 8 каналов
```

## Расширение до 50 ячеек

Схема на модулях по 8 каналов:

| Плата | Ячейки |
|---|---|
| Плата 1 | 1-8 |
| Плата 2 | 9-16 |
| Плата 3 | 17-24 |
| Плата 4 | 25-32 |
| Плата 5 | 33-40 |
| Плата 6 | 41-48 |
| Плата 7 | 49-56 |

В БД каждая ячейка должна знать:

- `controller_id`;
- `controller_address`;
- `relay_channel`.

Это позволит без изменения бизнес-логики перекидывать ячейки между контроллерами.

## Датчики закрытия

В MVP датчики не обязательны.

Но в БД уже должны быть поля:

- `has_close_sensor`;
- `close_sensor_controller_address`;
- `close_sensor_channel`.

В будущем можно использовать:

- геркон;
- концевик;
- микропереключатель.

Логика будущего сценария:

```text
пользователь нажал "Ячейка закрыта"
-> backend проверяет датчик
-> если датчик показывает закрыто, продолжить
-> если открыто, показать предупреждение
```

## Hardware layer

Бизнес-логика не должна знать детали конкретной платы.

Интерфейс:

```python
class LockController:
    def open_cell(
        self,
        controller_address: int,
        relay_channel: int,
        pulse_seconds: float = 1.0,
    ) -> None:
        ...
```

Реализации:

```text
MockLockController
UsbRelayController
ModbusRelayController
```

## MockLockController

Нужен для разработки без железа.

Поведение:

- принимает команду открытия;
- пишет в лог;
- может имитировать успех;
- может имитировать ошибку.

## Ошибки оборудования

Если замок не открылся:

- не менять остатки;
- перевести сессию в `error`;
- записать `open_cell_failed` или `relay_error`;
- показать пользователю ошибку;
- дать администратору посмотреть детали.

## Электробезопасность и монтаж

Для реального шкафа нужно предусмотреть:

- отдельный блок питания на замки;
- запас по току;
- защиту цепей;
- аккуратную разводку проводов;
- маркировку каналов;
- доступ к аварийному механическому открытию, если требуется;
- понятное соответствие `ячейка -> контроллер -> канал`.
