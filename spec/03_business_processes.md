# 03. Бизнес-процессы

## 1. RFID-авторизация

### Успешный сценарий

```text
Пользователь прикладывает RFID
-> система получает UID
-> ищет пользователя по rfid_uid
-> проверяет is_active
-> определяет роль
-> показывает главное меню
-> пишет access_event: login_success
```

### Неизвестный RFID

```text
Пользователь прикладывает RFID
-> UID не найден
-> показать "Ключ не найден"
-> записать access_event: unknown_rfid
-> доступ не давать
```

### Заблокированный пользователь

```text
Пользователь прикладывает RFID
-> UID найден
-> is_active = false
-> показать "Пользователь заблокирован"
-> записать access_event: access_denied
-> доступ не давать
```

## 2. Поиск товара

```text
RFID
-> Главное меню
-> Найти товар
-> ввод названия / SKU / штрихкода
-> система ищет товар
-> показывает список найденных товаров
-> пользователь выбирает товар
-> система показывает общий остаток и ячейки
```

Порядок поиска:

1. Точное совпадение `barcode`.
2. Точное совпадение `sku`.
3. Поиск по `name`.

Карточка товара должна показывать:

- название;
- SKU;
- штрихкод;
- единицу измерения;
- общий остаток;
- список ячеек с количеством;
- действия: `Положить`, `Забрать`, `История`.

## 3. Пополнение товара

```text
RFID
-> Положить товар
-> выбрать товар
-> выбрать ячейку
-> ввести количество
-> проверить права
-> проверить статус ячейки
-> проверить отсутствие активной сессии
-> создать cell_session типа fill
-> открыть ячейку
-> показать экран "Ячейка открыта"
-> пользователь кладет товар
-> пользователь закрывает ячейку
-> пользователь нажимает "Ячейка закрыта"
-> система переводит сессию в close_confirmed
-> пользователь подтверждает пополнение
-> система увеличивает stock_items.quantity
-> система пишет stock_movement fill
-> система завершает session
```

Важное правило:

Остаток увеличивается только после подтверждения закрытия и подтверждения операции.

Если пользователь отменил операцию после открытия:

- остаток не меняется;
- пишется `session_cancelled`;
- пишется причина отмены.

## 4. Выдача товара

```text
RFID
-> Забрать товар
-> выбрать товар
-> система показывает ячейки с остатком
-> выбрать ячейку
-> ввести количество
-> проверить достаточный остаток
-> проверить права
-> проверить статус ячейки
-> проверить отсутствие активной сессии
-> создать cell_session типа take
-> открыть ячейку
-> показать экран "Ячейка открыта"
-> пользователь забирает товар
-> пользователь закрывает ячейку
-> пользователь нажимает "Ячейка закрыта"
-> система переводит сессию в close_confirmed
-> пользователь подтверждает выдачу
-> система уменьшает stock_items.quantity
-> система пишет stock_movement take
-> система завершает session
```

Важное правило:

Остаток уменьшается только после подтверждения закрытия и подтверждения операции.

Если количества недостаточно:

- сессия не создается;
- ячейка не открывается;
- пользователь видит ошибку;
- событие можно записать в журнал.

## 5. Открытие без изменения товара

```text
RFID
-> Открыть ячейку
-> выбрать ячейку
-> проверить права
-> проверить статус ячейки
-> проверить отсутствие активной сессии
-> создать session open_only
-> открыть ячейку
-> пользователь выполняет обслуживание
-> пользователь закрывает ячейку
-> нажимает "Ячейка закрыта"
-> завершить session
```

Остатки не меняются.

## 6. Инвентаризация

Доступно только `admin` или `manager`.

```text
RFID
-> Инвентаризация
-> выбрать ячейку
-> открыть ячейку
-> показать содержимое
-> пользователь вводит фактические количества
-> пользователь закрывает ячейку
-> нажимает "Ячейка закрыта"
-> подтверждает результат
-> система сравнивает факт с учетом
-> обновляет stock_items
-> пишет stock_movement inventory или adjust
-> завершает session
```

Для каждого измененного товара нужно записать:

- `quantity_before`;
- `quantity_after`;
- разницу;
- пользователя;
- ячейку;
- session_id.

## 7. Активная сессия уже существует

Если пользователь пытается открыть ячейку, пока другая операция не завершена:

```text
новую ячейку не открывать
-> показать блокирующий экран
-> показать номер ячейки
-> показать пользователя
-> показать операцию
-> показать время начала
-> предложить допустимые действия
```

Доступные действия:

- `Ячейка закрыта`;
- `Отменить операцию`, если есть права;
- `Вызвать администратора`, если нет прав.

## 8. Перезапуск при активной сессии

При старте backend:

```text
записать system_startup
-> проверить активную cell_session
-> если есть активная session, показать блокирующий экран
-> новые открытия запретить
-> автоматически сессию не удалять
```

Зачем так:

- неизвестно, была ли физически закрыта ячейка;
- неизвестно, выполнил ли пользователь действие;
- автоматическое закрытие может испортить учет.

## 9. Ошибка открытия замка

```text
создана session opening
-> LockController.open_cell вызвал ошибку
-> записать access_event open_cell_failed или relay_error
-> перевести session в error
-> показать ошибку пользователю
-> остатки не менять
```

После ошибки должна быть возможность администратору посмотреть сессию и журнал.
