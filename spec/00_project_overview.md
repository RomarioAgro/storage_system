# 00. Обзор проекта

## Название

Локальная адресная система хранения с RFID и электронными замками.

## Цель

Создать систему для офисного склада мелких товаров, где пользователь авторизуется RFID-картой, выбирает действие, система проверяет права и открывает только нужную ячейку.

Система должна одновременно решать две задачи:

1. Физический контроль доступа к ячейкам.
2. Учет товаров, остатков и истории движений.

## Ключевые ограничения

- Система работает локально, без обязательного подключения к интернету.
- В MVP используется 8 ячеек.
- Архитектура должна позволить расширение до 100 ячеек.
- Все ячейки находятся в одном помещении.
- Закрытие ячейки в MVP подтверждается вручную.
- В будущем должны подключаться датчики закрытия.
- В один момент времени может быть активна только одна операция открытия.

## Модель предметной области

```text
Ячейка != товар
Ячейка = физическое место хранения
Товар = номенклатура
Остаток = связь товара и ячейки с количеством
```

Следствия:

- один товар может лежать в нескольких ячейках;
- одна ячейка может содержать несколько товаров;
- количество хранится в связке `товар + ячейка`;
- история движения пишется отдельно и не заменяется текущим остатком.

## Общая архитектура

```text
USB RFID-считыватель
        |
        v
Локальный терминал / мини-ПК / Raspberry Pi
        |
        +-- FastAPI backend
        +-- Локальная БД
        +-- Терминальный UI
        +-- Админ-панель
        |
        v
Hardware layer
        |
        +-- USB/RS485 релейные модули
        +-- Электронные замки ячеек
```

## Архитектурный принцип по оборудованию

Backend не должен напрямую управлять реле из бизнес-логики.

Нужен отдельный аппаратный слой:

```python
class LockController:
    def open_cell(
        self,
        controller_address: int,
        relay_channel: int,
        pulse_seconds: float = 1.0,
    ) -> None:
        ...
```

Минимальные реализации:

- `MockLockController` для разработки без железа;
- `UsbRelayController` для USB-реле;
- `ModbusRelayController` для RS485 Modbus RTU.

## Основные подсистемы

### Backend

Отвечает за:

- пользователей;
- RFID-авторизацию;
- роли и права;
- товары;
- ячейки;
- остатки;
- операции;
- сессии открытия;
- журнал доступа;
- интеграционный API.

### Terminal UI

Отвечает за рабочий экран на складе:

- приложить RFID;
- найти товар;
- положить товар;
- забрать товар;
- посмотреть содержимое ячейки;
- подтвердить закрытие ячейки;
- завершить или отменить операцию.

### Admin panel

Отвечает за управление:

- пользователями;
- ролями;
- товарами;
- ячейками;
- остатками;
- оборудованием;
- журналами;
- экспортом.

### Hardware layer

Отвечает за:

- открытие конкретного замка;
- работу с адресами контроллеров;
- работу с каналами реле;
- обработку ошибок оборудования;
- будущие датчики закрытия.

## Нефункциональные требования

- Простота эксплуатации.
- Работа без интернета.
- Устойчивость к перезапуску backend.
- Предсказуемая логика операций.
- Невозможность открыть две ячейки одновременно.
- Логирование всех важных событий.
- Возможность заменить mock-контроллер на реальный без переписывания бизнес-логики.
