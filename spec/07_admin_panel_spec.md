# 07. Админ-панель

## Назначение

Админ-панель нужна для настройки системы, управления справочниками, просмотра истории и обслуживания.

MVP может быть простым: серверные HTML-страницы или минимальный frontend поверх API.

## Доступ

Полный доступ:

- `admin`.

Частичный доступ может быть у:

- `manager`;
- `service`.

## Разделы

### 1. Пользователи

Функции:

- отдельная вкладка управления пользователями из админ-панели;
- кнопка `Открыть пользователей` на главной странице админки;
- список пользователей;
- создать пользователя;
- редактировать фамилию, имя, отчество и отдел;
- назначить роль;
- привязать RFID UID;
- заблокировать пользователя;
- активировать пользователя.

Поля пользователя:

- фамилия, обязательное поле;
- имя, обязательное поле;
- отчество;
- отдел;
- RFID UID;
- роль;
- активность;
- дата создания.

Создание и редактирование пользователей должно быть вынесено на отдельную
HTML-страницу админки, открываемую из главной админ-панели в новой вкладке
браузера.

### 2. Роли и права

В MVP можно сделать роли фиксированными.

Функции:

- просмотр ролей;
- просмотр матрицы прав.

В будущей версии:

- редактирование разрешений;
- кастомные роли.

### 3. Товары

Функции:

- отдельная вкладка управления товарами из админ-панели;
- кнопка `Открыть товары и группы` на главной странице админки;
- список товаров;
- поиск;
- создать товар;
- редактировать товар;
- деактивировать товар;
- посмотреть остатки;
- посмотреть историю.

Поля товара:

- название;
- SKU;
- штрихкод;
- единица измерения;
- внешний ID;
- активность.

Создание товаров и групп товаров должно быть вынесено на отдельную HTML-страницу
админки, открываемую из главной админ-панели в новой вкладке браузера.

### 4. Ячейки

Функции:

- отдельная вкладка управления ячейками из админ-панели;
- кнопка `Открыть ячейки` на главной странице админки;
- список ячеек;
- создать ячейку;
- редактировать ячейку;
- задать статус;
- привязать контроллер;
- задать канал реле;
- указать наличие датчика закрытия;
- посмотреть содержимое.

Создание, редактирование и блокировка ячеек должны быть вынесены на отдельную
HTML-страницу админки, открываемую из главной админ-панели в новой вкладке
браузера.

Статусы:

- `active`;
- `blocked`;
- `maintenance`.

### 5. Остатки

Функции:

- отдельная вкладка управления остатками из админ-панели;
- кнопка `Открыть остатки` на главной странице админки;
- просмотр остатков по товарам;
- просмотр остатков по ячейкам;
- фильтр по товару;
- фильтр по ячейке;
- переход к истории движения.

Прямое ручное изменение остатка лучше не делать обычной кнопкой.

Если нужно ручное исправление, оно должно быть оформлено как операция `adjust` или `inventory` с записью в историю.

Просмотр и создание строк остатков должны быть вынесены на отдельную
HTML-страницу админки, открываемую из главной админ-панели в новой вкладке
браузера.

Админка не должна позволять создать положительный остаток второго товара в
ячейке, где уже есть положительный остаток другого товара.

### 6. История движений

Функции:

- отдельная вкладка журналов и сессий из админ-панели;
- кнопка `Открыть журналы и сессии` на главной странице админки;
- список движений;
- фильтр по товару;
- фильтр по ячейке;
- фильтр по пользователю;
- фильтр по типу операции;
- фильтр по дате;
- экспорт.

Показывать:

- дата;
- пользователь;
- товар;
- ячейка;
- тип движения;
- количество;
- остаток до;
- остаток после;
- комментарий.

Время:

- события движений хранятся в UTC;
- в таблице истории движений дата показывается в локальном часовом поясе
  объекта `UTC+03:00` (`Europe/Moscow`);
- экспорт истории движений должен использовать тот же локальный формат времени.

История движений должна быть вынесена на отдельную HTML-страницу админки
вместе с журналом доступа и сессиями открытия. Страница открывается из главной
админ-панели в новой вкладке браузера.

### 7. Журнал доступа

Функции:

- отдельная вкладка журналов и сессий из админ-панели;
- кнопка `Открыть журналы и сессии` на главной странице админки;
- просмотр событий;
- фильтр по пользователю;
- фильтр по RFID UID;
- просмотр IP-адреса клиента;
- фильтр по ячейке;
- фильтр по типу события;
- фильтр по результату;
- экспорт.

Время:

- события хранятся в БД в UTC;
- в таблице журнала доступа время показывается в локальном часовом поясе
  объекта `UTC+03:00` (`Europe/Moscow`);
- рядом с временем должна быть понятная подпись или формат со смещением,
  например `2026-06-10 13:00:00 +03:00`;
- фильтры по периоду вводятся пользователем в локальном времени и на backend
  преобразуются в UTC;
- экспорт журнала доступа должен использовать тот же локальный формат времени,
  чтобы CSV/XLSX совпадал с тем, что администратор видит в UI.

Отображение:

- пользователь в таблице журнала доступа показывается как `Фамилия Имя`, а не
  как числовой `user_id`;
- IP-адрес клиента показывается отдельной колонкой, если он известен.
- для операций через терминал и API IP показывается у событий старта сессии,
  открытия ячейки, подтверждения закрытия, завершения и отмены;
- если пользователь работает прямо на сервере через loopback, в журнале
  отображается IP сервера в локальной сети.

События:

- успешный вход;
- неизвестный RFID;
- отказ в доступе;
- открытие ячейки;
- ошибка реле;
- подтверждение закрытия;
- старт системы;
- завершение/отмена сессии.

Журнал доступа должен быть вынесен на отдельную HTML-страницу админки вместе с
историей движений и сессиями открытия. Страница открывается из главной
админ-панели в новой вкладке браузера.

### 8. Сессии открытия

Функции:

- отдельная вкладка журналов и сессий из админ-панели;
- кнопка `Открыть журналы и сессии` на главной странице админки;
- список сессий;
- просмотр активной сессии;
- просмотр завершенных сессий;
- аварийное завершение активной сессии;
- отмена зависшей операции.

Время:

- timestamps сессий хранятся в UTC;
- список сессий открытия показывает время создания и lifecycle timestamps в
  локальном часовом поясе объекта `UTC+03:00` (`Europe/Moscow`);
- фильтры по периоду для сессий должны принимать локальное время и
  преобразовывать его в UTC перед запросом к БД.

Аварийное завершение должно быть доступно только администратору.

При аварийном завершении обязательно:

- указать причину;
- записать событие;
- не менять остатки автоматически, если операция не была подтверждена.

Сессии открытия должны быть вынесены на отдельную HTML-страницу админки вместе
с историей движений и журналом доступа. Страница открывается из главной
админ-панели в новой вкладке браузера.

### 9. Оборудование

Функции:

- отдельная вкладка управления оборудованием из админ-панели;
- кнопка `Открыть оборудование` на главной странице админки;
- список контроллеров;
- создать контроллер;
- редактировать порт и адрес;
- включить/выключить контроллер;
- тест открытия канала;
- просмотр ошибок оборудования.

Тест открытия канала должен быть защищен правами.

Просмотр контроллеров оборудования должен быть вынесен на отдельную
HTML-страницу админки, открываемую из главной админ-панели в новой вкладке
браузера.

### 10. Экспорт

Минимальные экспорты:

- товары;
- текущие остатки;
- история движений;
- журнал доступа.

Форматы:

- CSV для MVP;
- XLSX можно добавить позже.

## Минимальный набор для MVP

Чтобы не раздуть первую версию, в MVP обязательно сделать:

- пользователи;
- товары;
- ячейки;
- остатки;
- история движений;
- журнал доступа;
- активная сессия;
- аварийное завершение сессии.
