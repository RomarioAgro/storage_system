# 09. Тестирование и приемка

## Цель тестирования

Проверить не только API, но и целостность процесса:

```text
RFID -> права -> сессия -> замок -> закрытие -> подтверждение -> остаток -> история
```

## Уровни тестирования

### Unit-тесты

Проверяют сервисы:

- авторизация;
- права;
- поиск товаров;
- расчет остатков;
- создание движений;
- переходы статусов сессии;
- запрет второй активной сессии;
- обработка ошибок оборудования.

### Integration-тесты

Проверяют API и БД:

- POST `/api/auth/rfid`;
- операции пополнения;
- операции выдачи;
- подтверждение закрытия;
- подтверждение операции;
- отмена операции;
- история товара;
- журнал доступа.
- timezone-aware UTC timestamps после записи, commit/refresh и чтения из новой
  SQLite-сессии;
- API-сериализацию timestamps с UTC offset.

### CI-тесты

GitHub Actions должен запускать:

- установку Python 3.12;
- `ruff check .`;
- PostgreSQL service container;
- `alembic upgrade head` на PostgreSQL;
- `pytest` с `POSTGRES_TEST_DATABASE_URL`.

### Hardware-тесты

Проверяют:

- чтение RFID;
- открытие каждого канала реле;
- соответствие канала физической ячейке;
- импульс открытия;
- работу блока питания под нагрузкой;
- поведение при ошибке реле.

### UI-тесты

Проверяют:

- пользователь может пройти основной сценарий;
- ошибки понятны;
- кнопки соответствуют роли;
- активная сессия блокирует новые открытия;
- после завершения операции UI возвращается к RFID.

## Критерии приемки MVP

MVP считается готовым, если выполнены все пункты ниже.

### RFID и доступ

- RFID-авторизация работает.
- Неизвестный RFID отклоняется.
- Заблокированный пользователь отклоняется.
- Отказ в доступе записывается в журнал.
- Пользователь видит только разрешенные действия.

### Товары и остатки

- Товары создаются.
- Товары редактируются.
- Товары ищутся по названию.
- Товары ищутся по SKU.
- Товары ищутся по штрихкоду.
- Остатки ведутся по ячейкам.
- Один товар может лежать в нескольких ячейках.
- Одна ячейка не может содержать положительный остаток разных товаров.
- Общий остаток считается корректно.
- Терминальный UI показывает обзор всех товаров с остатками и ячейками с
  постраничным выводом на 20, 50 или 100 строк.
- Обзор всех товаров позволяет включить товары с нулевым остатком и товары без
  ячеек.
- Терминальный UI показывает обзор всех ячеек с товарами и остатками с
  постраничным выводом на 20, 50 или 100 строк.

### Пополнение

- Пользователь может положить товар в выбранную ячейку.
- Ячейка открывается только после проверки прав.
- Остаток не меняется сразу после открытия.
- Остаток увеличивается только после подтверждения закрытия и операции.
- Создается `stock_movement fill`.
- Создается запись в журнале доступа.

### Выдача

- Пользователь может забрать товар из выбранной ячейки.
- Система показывает ячейки, где есть товар.
- Система проверяет достаточный остаток.
- При недостаточном остатке ячейка не открывается.
- Остаток не меняется сразу после открытия.
- Остаток уменьшается только после подтверждения закрытия и операции.
- Создается `stock_movement take`.

### Отмена

- Операцию можно отменить.
- При отмене остаток не меняется.
- Сессия получает статус `cancelled`.
- Причина отмены сохраняется.
- Событие отмены пишется в журнал.

### Одна активная сессия

- Вторая ячейка не открывается при активной сессии.
- При попытке открыть вторую ячейку показывается блокирующий экран.
- В БД есть защита от двух активных сессий.
- Проверка работает даже при параллельных запросах.

### Время и аудит

- Все `created_at`, `updated_at` и lifecycle timestamps сессий возвращаются как
  timezone-aware UTC.
- API отдает timestamp-значения с явным UTC offset.
- В коде не используется `datetime.utcnow()`.
- Журнал доступа в админ-панели отображает события в локальном времени
  `UTC+03:00` (`Europe/Moscow`), хотя хранение в БД остается UTC.
- Журнал доступа в админ-панели показывает IP-адрес клиента и пользователя в
  формате `Фамилия Имя`, а не числовой ID.
- События операции в журнале доступа наследуют IP terminal/API запроса; при
  локальном loopback-доступе отображается LAN IP сервера.
- История движений и список сессий открытия в админ-панели отображают время в
  локальном времени `UTC+03:00` (`Europe/Moscow`).
- История движений в админ-панели показывает товар по названию, а не по
  числовому `product_id`.
- История движений, журнал доступа и список сессий открытия доступны на
  отдельной странице админки, открываемой из главной админ-панели в новой
  вкладке.
- Фильтр журнала доступа по периоду интерпретирует пользовательский ввод как
  локальное время `UTC+03:00` и корректно находит UTC-события в БД.

### Перезапуск

- Активная сессия сохраняется после перезапуска backend.
- При старте backend пишется `system_startup`.
- Если активная сессия есть, новые открытия запрещены.
- Активная сессия не завершается автоматически.

### Админка

- Админ может управлять пользователями.
- При создании и редактировании пользователя фамилия и имя обязательны.
- Пользователь хранит фамилию, имя, отчество и отдел отдельными полями.
- Админ может управлять товарами.
- Админ может управлять ячейками.
- Админ открывает остатки с главной страницы админки в отдельной вкладке.
- Админ открывает историю движений, журнал доступа и сессии открытия с главной
  страницы админки в отдельной вкладке.
- Админ открывает оборудование с главной страницы админки в отдельной вкладке.
- Админ может аварийно завершить сессию с причиной.

### Оборудование

- Mock-контроллер работает для разработки.
- Реальный контроллер открывает нужный канал.
- Ошибка открытия не меняет остатки.
- Ошибка открытия пишется в журнал.

## Набор обязательных тест-кейсов

### TC-01. Успешный RFID-вход

Дано: активный пользователь с RFID.  
Когда: прикладывает карту.  
Тогда: система показывает меню и пишет `login_success`.

### TC-02. Неизвестный RFID

Дано: UID отсутствует в БД.  
Когда: карта приложена.  
Тогда: доступ запрещен, пишется `unknown_rfid`.

### TC-03. Пополнение товара

Дано: товар и активная ячейка.  
Когда: пользователь кладет 5 шт и подтверждает операцию.  
Тогда: остаток увеличивается на 5, история содержит `fill`.

### TC-04. Отмена пополнения

Дано: сессия пополнения открыта.  
Когда: пользователь отменяет операцию.  
Тогда: остаток не меняется, сессия `cancelled`.

### TC-05. Выдача товара

Дано: в ячейке есть 5 шт.  
Когда: пользователь забирает 3 шт и подтверждает.  
Тогда: остаток становится 2, история содержит `take`.

### TC-06. Недостаточный остаток

Дано: в ячейке есть 2 шт.  
Когда: пользователь пытается забрать 3 шт.  
Тогда: ячейка не открывается, остаток не меняется.

### TC-07. Блокировка второй ячейки

Дано: есть активная сессия по ячейке 2.  
Когда: пользователь пытается открыть ячейку 3.  
Тогда: ячейка 3 не открывается, показывается блокирующий экран.

### TC-08. Перезапуск с активной сессией

Дано: есть активная сессия.  
Когда: backend перезапущен.  
Тогда: активная сессия остается, новые открытия запрещены.

### TC-09. Ошибка реле

Дано: контроллер возвращает ошибку.  
Когда: пользователь пытается открыть ячейку.  
Тогда: сессия `error`, остатки не меняются, журнал содержит ошибку.

### TC-10. Инвентаризация

Дано: manager проводит инвентаризацию.  
Когда: фактическое количество отличается.  
Тогда: остаток обновлен, история содержит `inventory` или `adjust`.
