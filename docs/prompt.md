# Codex prompt: RFID storage MVP with subagents

Ты работаешь над проектом локальной RFID-системы хранения с электронными замками.

Твоя роль: главный инженер-оркестратор. Проект большой, поэтому не пытайся решать все одним проходом. Используй subagent workflow для анализа, а реализацию выполняй управляемыми пакетами.

## 3. Главный инвариант системы

В один момент времени может быть открыта или активна только одна ячейка.

Новая ячейка не должна открываться, пока текущая операция не завершена:

ячейка открыта -> пользователь выполняет действие -> закрывает ячейку -> нажимает "Ячейка закрыта" -> подтверждает или отменяет операцию -> только после этого можно открыть следующую ячейку.

Этот инвариант должен быть защищен:

* бизнес-логикой;
* транзакциями;
* API-проверками;
* PostgreSQL partial unique index;
* тестами повторного или конкурентного открытия.

Активными считаются статусы cell_sessions:

* created;
* opening;
* opened;
* waiting_close;
* close_confirmed.

Для PostgreSQL нужен partial unique index:

```sql
CREATE UNIQUE INDEX only_one_active_cell_session
ON cell_sessions ((true))
WHERE status IN (
    'created',
    'opening',
    'opened',
    'waiting_close',
    'close_confirmed'
);
```

Для SQLite dev-режима обеспечь эквивалентную защиту на уровне сервисов и тестов. Если SQLite не поддерживает нужную конструкцию так же, как PostgreSQL, явно зафиксируй это в комментарии, миграции или README.

## 8. Hardware layer

Backend не должен напрямую управлять реле из бизнес-логики.

Все открытие ячеек должно идти через hardware layer:

```python
class LockController:
    def open_cell(
        self,
        controller_address: int,
        relay_channel: int,
        pulse_seconds: float = 1.0,
    ) -> None:
        ...
```

Нужны реализации:

* MockLockController, рабочая для разработки и тестов;
* UsbRelayController, только заготовка без реального протокола;
* ModbusRelayController, только заготовка без реального протокола.

Не реализуй реальные протоколы USB relay или Modbus RTU в MVP. Достаточно интерфейса, заглушек и понятных точек расширения.

## 9. API MVP

Реализуй или доработай API.

### RFID auth

```http
POST /api/auth/rfid
```

Поведение:

* найти активного пользователя по `rfid_uid`;
* если пользователь найден, вернуть user info и записать `login_success`;
* если RFID неизвестен, отклонить запрос и записать `unknown_rfid`.

### Products

```http
GET /api/products?query=...
POST /api/products
GET /api/products/{product_id}/stock
GET /api/products/{product_id}/history
```

Порядок поиска:

1. точное совпадение `barcode`;
2. точное совпадение `sku`;
3. поиск по `name`.

### Cells

```http
GET /api/cells
GET /api/cells/{cell_id}/contents
```

### Fill operation

```http
POST /api/operations/fill/start
POST /api/sessions/{session_id}/confirm-close
POST /api/operations/fill/{session_id}/confirm
```

Правила:

* проверить пользователя, права, товар, ячейку;
* проверить отсутствие активной сессии;
* создать `cell_session` типа `fill`;
* открыть ячейку через LockController;
* перевести сессию в `waiting_close`;
* не менять остаток на старте;
* после `confirm-close` и `confirm` увеличить остаток;
* создать `stock_movement` типа `fill`;
* завершить сессию.

### Take operation

```http
POST /api/operations/take/start
POST /api/sessions/{session_id}/confirm-close
POST /api/operations/take/{session_id}/confirm
```

Правила:

* проверить достаточный остаток;
* проверить права;
* проверить отсутствие активной сессии;
* открыть ячейку через LockController;
* не менять остаток на старте;
* после `confirm-close` и `confirm` уменьшить остаток;
* создать `stock_movement` типа `take`;
* завершить сессию.

### Cancel

```http
POST /api/sessions/{session_id}/cancel
```

Правила:

* остатки не менять;
* перевести сессию в `cancelled`;
* записать `session_cancelled`.

### Open only

Реализуй открытие ячейки без изменения остатков.

Правила:

* operation_type = `open_only`;
* открыть ячейку;
* дождаться ручного `confirm-close`;
* завершить session;
* не создавать stock_movement для изменения остатков.

Запрещено:

* подключать реальное железо;

* уходить от локального режима работы;

Разрешено:
