Отчет Codex: RFID storage MVP

Что реализовано

  • Усилен hardware contract: строгий LockController.open_cell(int, int, float), docstrings, проверяемый MockLockController с историей вызовов и fail-mode.
  • Операции открытия фиксируют сессию в статусе opening до вызова lock controller.
  • Добавлена проверка hardware mapping ячейки до открытия.
  • Конфликт активной сессии на DB flush маппится в ActiveSessionExistsError.
  • Исправлен порядок поиска товаров: barcode, затем SKU, затем name.
  • /api/sessions/active возвращает данные, достаточные для блокирующего экрана.
  • Добавлен Jinja2 terminal UI: RFID, меню, поиск, карточка товара, fill/take/open_only, confirm-close, confirm/cancel, active-session blocker.
  • Добавлена минимальная admin panel: пользователи, товары, ячейки, остатки, движения, журнал доступа, сессии, оборудование, аварийная отмена.
  • Terminal UI переведен на локальную signed-cookie session после RFID login; user_id больше не передается через формы terminal UI.
  • Менеджеры и администраторы получили кнопку Создать товар в terminal UI; доступ защищен правом manage_products.
  • Добавлена иерархическая группировка товаров: product_categories с parent_id и products.category_id.
  • Категории доступны в API, admin UI, terminal product creation и seed-данных.
  • Inventory переведен в полноценный lifecycle: start, open lock, confirm close, confirm inventory, stock movement, complete.
  • Admin panel расширена inline-редактированием и блокировкой пользователей/ячеек.
  • Добавлены concurrency test для второго открытия и PostgreSQL integration check, который запускается при POSTGRES_TEST_DATABASE_URL.
  • Seed приведен к ТЗ: роли, RFID-пользователи, mock controller, 8 ячеек, товары и стартовые остатки; runtime output переведен на logging.
  • Добавлены приемочные pytest-сценарии для RFID, поиска, DB constraints, операций, access events и UI-блокировки.

Как запустить проект

  1. Установить Python 3.12+.
  2. python -m venv .venv
  3. .venv\Scripts\python.exe -m pip install -e .[dev]
  4. .venv\Scripts\python.exe -m app.seed
  5. .venv\Scripts\python.exe -m uvicorn app.main:app --reload
  6. Открыть http://127.0.0.1:8000/terminal или http://127.0.0.1:8000/admin.

Как запустить тесты

.venv\Scripts\python.exe -m pytest

  • qa_specialist: перечислил обязательные тесты для RFID, операций, остатков, access events и UI blocking.

Решения оркестратора

  • Критический путь выбран как backend invariant, terminal blocker, operation tests, затем отчет.
  • UI реализован server-rendered Jinja2 без React/Vue/Angular.
  • Inventory переведен в общий lifecycle; прямой endpoint /inventory/set теперь отказывает с 409.
  • PostgreSQL migration не менялась, так как требуемый partial unique index уже есть.

Ограничения и риски

  • Python 3.12 установлен локально в проекте, а не через системный package manager.
  • UI session использует development default secret; для production его нужно задавать через окружение.
  • PostgreSQL integration-тест добавлен, но в текущем окружении пропускается без POSTGRES_TEST_DATABASE_URL.
  • Конкурентные production-сценарии требуют row locks/advisory locks и более строгих транзакционных границ.
